## T-0042 BOOM store token handoff to owned-manager D

- T-0042 remains in progress on Gate 1 under accepted ADR-0045. This slice adds
  no new ADR or EXP and does not change the ADR-0043 common bridge or its
  one-outstanding contract.
- A repository-owned `{valid, epoch, sequence}` request metadata field now
  follows the already-authorized pinned BOOM store from the LSU request through
  the DCache request pipeline and uncached TileLink A request. The owned manager
  samples it only on the exact target `Put` A acceptance, retains it in the
  existing one-outstanding state, and reports the same fields with the matching
  D completion. ROB, STQ, PC, address, branch mask, lane, and TileLink source
  remain diagnostic or transport context rather than semantic identity.
- Classification fails closed when the metadata is absent or malformed. This
  diagnostic uses fixed epoch 1 and one local sequence and does not yet
  implement epoch rotation, reset-outstanding handling, exhaustion, retry,
  stale/duplicate-token, stripped-field, source-reuse/backpressure, or
  loader/FESVR/Debug negatives. It does not feed `InitiatorCpu` or promote the
  ADR-0043 bridge.
- The first connected RTL run reached the BOOM-local authorization ledger with
  token `(1, 1)`, but the manager observed invalid zero metadata. Source
  inspection found that the pinned DCache partially assigned the request from
  `s2_req` into the MSHR request, so adding members to `BoomDCacheReq` did not
  automatically preserve them. Explicit `s2_req -> MSHR` assignments corrected
  the path. A subsequent successful RTL trace was initially rejected because
  the verifier compared differently zero-padded hexadecimal address strings;
  numeric address comparison corrected that verifier-only failure. Both failed
  attempts remain diagnostic evidence and make no attribution claim.
