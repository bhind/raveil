  RISC-V/Sonatine control and authority path. ADR-0019 makes Linux a
  non-authoritative development and transport-validation host.
- Added a fixed 32-byte request/completion v1 ABI with PING/NOP only and a
  pure-C one-inflight core. Invalid magic, version, size, flags, and opcode
  fail closed; busy and empty states remain distinct.
- Added Linux-only same-UID `SOCK_SEQPACKET` daemon/client sources. The daemon
  requires an absolute `XDG_RUNTIME_DIR`, creates a private endpoint under
  umask 0077, rejects partial messages with `MSG_TRUNC`, and exposes no network,
  root, kernel module, pointer, file-descriptor passing, DMA, MMIO, or
  Experience boundary.

## T-0030 bounded JobDescriptor and CompletionRecord

- Accepted ADR-0020 and added a platform-neutral little-endian, pointer-free
  JobDescriptor/CompletionRecord v1 contract. The schema caps each job at four
  generation/version/range/effect object references and requires explicit
  runtime/input/output/scratch ceilings.
- Completion validation requires nonzero claimed execution epoch, sequence,
  and cookie; T-0031 still owns issuance and replay state. Executed outputs
  must be the job's WRITE objects with advanced versions;
  rejected/cancelled/fault observations carry no outputs.
- Structural validation is deliberately not admission, semantic approval,
  commit, visibility, or Experience authority. ObjectManifest/table lifecycle
  and rings remain T-0031; Linux still transports only PING/NOP.
- `scripts/ci-local.sh` exited 0 with all 55 tests and the unchanged Sonatine
  release/debug/DWARF/QEMU checks. The T-0030 strict-C11 host test passed under

## T-0031 Sonatine object table and job rings

- Accepted ADR-0021 and added the fixed 64-byte ObjectManifest v1 contract.
  The validator rejects malformed headers, reserved data, invalid access and
  backing combinations, zero identity/version/size fields, and writable
  immutable objects.
- Added a Sonatine-owned eight-entry object table, four-entry submission and
  completion rings, and four-entry inflight ledger. Admission checks exact
  64-bit ID, manifest generation/version, range, and permitted effect without
  treating the ID as a capability or truncating it to 32 bits.
- Sonatine issues boot-scoped epoch, sequence, and non-cryptographic cookie
  bindings. Wrong or duplicate completions do not consume pending state; valid
  completions post and consume once. `EXECUTED` deliberately leaves the
  visible object version unchanged for T-0033 commit/rollback.
- The seed is single-hart kernel-owned state. It adds no U-mode syscall, Linux
  authority, MMIO, DMA, IRQ, shared memory, reset protocol, physical storage,
  Experience write, or performance claim.
- The first full RV64 run exposed an undefined freestanding `memset` generated
  by aggregate zero initialization. `sonatine/src/runtime.c` now supplies the
  same bounded byte-loop primitive as its existing `memcpy`; the complete
  verification was then rerun from the start.
