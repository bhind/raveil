# Raveil v0.0000000000007 — Native Command Graph showcase

Status: Published GitHub Pre-release

This candidate adds T-0103's synthetic Native Command Graph walkthrough while
preserving the bounded workspace, tensor Graph MVP, Sonatine, Linux harness,
Experience, and earlier experiment evidence.

## Run the walkthrough

```sh
mkdir -p /tmp/raveil-showcase
python3 -m raveil showcase list
python3 -m raveil showcase prepare --workspace /tmp/raveil-showcase \
  --scenario showcase-incremental --nodes 16
python3 -m raveil showcase run --workspace /tmp/raveil-showcase \
  --scenario showcase-incremental --nodes 16
python3 -m raveil showcase mutate --workspace /tmp/raveil-showcase \
  --scenario showcase-incremental --nodes 16 --node 0
python3 -m raveil showcase run --workspace /tmp/raveil-showcase \
  --scenario showcase-incremental --nodes 16
```

The output visibly separates graph topology/admission/semantic hashes,
sequential and same-cap direct controls, DAG construction/execution/end-to-end,
observed parallelism, candidate-only interval, and the baseline-first total.
It also shows 16 initially executed nodes followed by a deterministic one-input
change that can execute one node and reuse 15 verified showcase artifacts.

## Evidence and limits

The workload is synthetic ordinary host file sorting, run through fixed
allowlisted direct argv with no shell. It is `host-development-smoke` /
`development-non-claim`; the displayed single-run timing is not a speedup or
performance claim. `control-small` intentionally permits overhead/no-win.
EXP-0004 remains Planned and this candidate contains neither a claim manifest
nor a research bundle.

The cache is showcase-only. `CommandGraphExecutor` reports
`production_reuse=not-implemented`; T-0104 owns any production design.
Experience is explicitly unconnected and advice-only. Native execution uses the
ordinary host ARM64/x86-64 ISA; no special Raveil ISA, FPGA, ASIC, or Sonatine
performance effect is claimed. No assets or hosted CI/CD workflow are planned.

Publication requires an exact fresh-clone audit, the owner-approved tag,
target SHA, remote, public prerelease visibility, and zero assets. Existing
tags and GitHub Releases are immutable and will not be moved or modified.
