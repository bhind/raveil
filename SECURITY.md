# Security reporting

Do not open a public GitHub Issue for a suspected vulnerability, credential,
private artifact, personal data exposure, or unsafe exploit detail. Notify the
repository owner or Project Manager through an already approved private channel
and initially provide only the affected revision, impact, and a safe locator.

Do not transmit secrets, internal URLs or hostnames, absolute user paths,
unpublished evidence contents, third-party source or document excerpts, patent
claims, or standards-draft text. Preserve relevant local evidence without
changing it and share additional detail only after a private handling path is
agreed.

Ordinary non-sensitive defects use the public bug template. Repository TODO,
STATUS, ADR, EXP, tests, and release history remain authoritative; a private or
public report does not by itself establish a project fact or legal conclusion.
